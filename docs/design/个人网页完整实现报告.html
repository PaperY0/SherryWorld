02 · 美感方向：黑粉、留白、克制的体积感

以 Apple 官方产品页作为视觉参考对象，采用大主体、清楚的文字层级、充足留白和按章节展开的叙事。本方案是针对你的网站做出的设计选择，不代表复制 Apple 的资产、字体授权或具体页面。参考入口：Apple MacBook Air。

个人特色落在三个地方：像你的角色、你自己的项目与故事、贯穿整页的柔粉色。黑色负责秩序与对比，粉色负责温度；两种主题共用同一排版、人物和内容。

普通标题、品牌字和正文在 Dark 模式中采用白色系；选中的粉色主题按钮与粉色 EXPLORE 用深色文字，确保阅读清晰。次级文字、按钮状态与正文的实际对比度在开发时检查，以上色值是起始设计值。

排版和空间

桌面内容区建议最大宽度 1120–1200px，页面两侧留出呼吸空间；手机采用约 20–24px 安全边距。章节之间用明显的纵向留白建立节奏，标题比正文更有存在感，正文保持舒服的行距。

主标题采用清楚的无衬线字，中文正文使用可靠的系统字体回退。字体选择先检查中英文一致性和实际授权，不把某个商业字体的使用当作默认条件。中文内容为主，英文用于栏目名、品牌和简短标题；后续有英文求职需求再加入完整英文版本。

项目区采用大图与短文并排的编辑式布局，生活区采用照片与小段文字交错排列。照片墙有视觉节奏，也保留稳定的阅读顺序。页面不堆砌大面积毛玻璃、金属环、过多标签和持续闪烁的光效。

04 · 首屏与滚动叙事

场景 A：人物序幕

角色上半身居中，头部和眼镜是视觉焦点，胸口以下自然裁切。根据相机和屏幕比例保证头顶完整可见，桌面初始顶端建议留出约 8%–12% 的视觉余量，且不与顶部控制相撞。手机和短屏按实际可视高度重新取景。

角色保留深色长发、轻薄中分刘海、黑框眼镜、微眯眼与克制嘴角，表现略拽而从容的态度。Light 与 Dark 使用同一模型、姿态和取景，只切换服装材质颜色及灯光。

首屏没有原先的 MY OWN WAY、介绍文案、EXPLORE 和导航菜单。PERSONAL SPACE 与主题按钮是实际网页文字，人物和背景使用独立素材，避免把 UI 固定在整张图中。

场景 B：滚动进入欢迎首页

用一段与滚动进度对应的连续时间线：人物缓慢缩小、后移，粉色光晕轻微扩散；标题按 A WORLD → OF → MY OWN 三组出现，全部大写。最后中央出现 EXPLORE。这里采用“一句话分组浮现”，不重复铺满整屏。

文字是可选择、可访问的网页元素；移动端随屏宽缩放，不能溢出。向上滚动时可返回人物序幕；快速滚动直接得到对应位置的状态，避免排队播放多个入场动画。

场景 C：进入个人世界

点击 EXPLORE 后，按钮短暂回应，标题淡出，镜头轻微推进，柔粉光晕扩散，然后关于我与精选项目进入。转场建议 900–1200ms，最终定位到个人世界内容起点。

继续向下滚动也能进入内容，不用按钮把页面锁住。减少动态偏好下取消大幅镜头推进，保留短淡入或直接定位。返回首页时恢复合理的滚动位置和当前主题。

动效建议值

行为 初始建议 约束
柔粉光晕 16–24 秒缓慢漂移一轮 不闪烁，不覆盖正文
静息呼吸 4–6 秒低幅度循环 肩部与胸腔自然变化
自然眨眼 约 3–7 秒随机间隔 与既有表情兼容
鼠标跟随 视线先动，头部平滑跟随 头部水平约 ±8°、垂直约 ±5°
拖动观察 水平约 ±20°的小范围侧看 纵向页面滚动优先
主题切换 400–600ms 不重载模型，不重置滚动
内容进入 300–500ms，小幅上移 正文不持续移动

这些是设计起点，不是已经测量或验收的结果。模型完成后根据观感调整，尤其检查眼镜穿模、眼睛翻转和头发与肩膀相撞。

05 · 项目展示：环形画廊与完整目录

项目区采用用户参考图中的横向弧形封面带，保留简洁留白和黑粉双主题。作品封面从上方依次落入弧形一横排，中央正面、两侧略有透视；默认从右向左循环。鼠标向左移动就向左流动，向右移动就反向，停止移动后平滑恢复默认向左。按住可拖动，纵向滚轮保持正常网页滚动。

点击作品封面暂停循环并打开介绍面板，包含项目名称、说明、本人职责、当前状态、GitHub 和可用的 Demo；关闭后回到原参观位置。面板的 GitHub 按钮打开仓库，封面本身不会在拖动时误跳转。保留暂停、前后切换和目录入口，手机与减少动态偏好也可正常参观。

12 · 真正的 3D 人物制作路线

现有 PNG 是造型与灯光参考，不能直接提供眼球跟随、眨眼、头部骨骼动作和真实侧面旋转。图片倾斜与分层动画适合先验证页面节奏，但必须标为视觉原型。

路线 能交付的效果 适用位置
图片分层或 2.5D 视觉原型 浮动、轻微视差、整体倾斜 先验证首屏比例和转场；不算最终真实 3D
基础头像模型定制 较快获得可旋转角色，需调整发型与脸部 作为候选，先比较本人辨识度与风格
根据概念稿定制 3D 模型 控制脸、发型、眼镜、材质和表情 推荐最终路线；外形与网页表现最可控

建议先完成定制造型和动作的小样，再投入全站动效。使用 AI 辅助生成网格时，仍需检查拓扑、眼睛、发丝、背面、材质和骨骼，不能把自动输出当作最终可用模型。

模型交付清单

  • 可编辑模型源文件及网页用 GLB；同一模型共用 Light / Dark 材质方案。
  • 头、颈、肩、胸部的必要骨骼；眼球可独立控制；眼皮包含眨眼形变或等效控制。
  • 深色头发采用适合网页的发束造型；眼镜独立对象，与头骨绑定；镜片不遮挡眼睛。
  • 两套服装颜色：哑光黑与珍珠灰，材质可直接切换。
  • 静息呼吸、眨眼、轻转头动作；现有略拽表情作为基准。
  • 正面及允许侧看角度的校验图；手机与桌面取景参考。
  • 纹理、材质、对象与动作命名清晰，提供资源使用权说明和必要的压缩解码配置。

网页加载使用 glTF / GLB 资产。Three.js 的官方 GLTFLoader 文档提供 glTF 2.0 加载及压缩资源相关接口。加载器能读取模型，不会自动补出缺失的骨骼、动作或表情。

13 · 技术架构建议

推荐 Next.js + TypeScript + React Three Fiber / Three.js + GSAP ScrollTrigger。内容以本地结构化数据与 Markdown / MDX 管理，先不建设账号系统和后台。开始开发时根据当前稳定版及官方兼容范围锁定依赖，不在报告里猜测未来的小版本号。

React Three Fiber 是 Three.js 的 React 渲染器，适合把人物场景作为独立组件；React 与 Fiber 的主要版本需要配套，见 官方介绍。ScrollTrigger 可将动画与滚动进度关联，支持固定区段和随滚动推进的时间线，见 官方文档。

Next.js 用于内容路由、详情页与分享信息；项目案例与文章不依赖 Canvas 才能显示。其 Metadata 与 OG 图片文档可作为分享标题、描述和预览图的实现依据。

替代方案是 React + Vite：适合较小的纯前端展示，基础结构更直接；多详情页的预渲染、分享信息与路由需另行规划。考虑长期维护项目案例、故事与旅行详情，本报告优先建议 Next.js。这个选择不意味着你已经具备相应框架能力。

15 · 性能、移动端与可访问性

美感需要稳定的加载与阅读体验。先显示文字、基础布局和角色静态预览，模型与动作加载成功后再替换。模型失败时保留角色图与全部内容入口，清楚区分静态回退和真实 3D。

建议首轮性能预算：压缩模型争取约 5–8MB，初始可见纹理和模型合计争取不超过约 12MB；桌面动画目标接近 60fps，常见手机争取稳定 30fps；这些都需要真实设备测试，不能当作已达到的成绩。若超预算，先降低不可见网格、纹理分辨率、透明材质层数和像素比。

只创建必要的 3D 渲染实例；看不到人物、页面切到后台或开启减少动态时暂停无必要的持续更新。退出场景时释放图形资源。项目与旅行图片按需加载，模型解码资产正确部署，照片占位提前保留尺寸。

手机保持人物头顶与主题按钮安全间距，不照搬桌面人物大小。移动设备使用低负担灯光、适度纹理和拖动观察；手势优先保证页面纵向滚动。照片放大层有关闭入口与返回焦点，主题切换和 EXPLORE 可用键盘操作。

减少动态通过标准 prefers-reduced-motion 检测，采用静态或轻淡入路径，参见 MDN 文档。正文、项目详情、联系方式和搜索分享信息都在普通网页结构中，不写在 Canvas 里。
