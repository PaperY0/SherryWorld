PaperY · 个人网页落地与完善计划

日期：2026-10-03。这是完整交付路线与验收任务清单，作为后续各阶段实施的依据；本轮不创建正式网站工程。

执行方式：后续使用 executing-plans 按阶段推进。每阶段形成可查看成果，完成验收再进入依赖它的工作。本计划没有安排额外子代理或自动发布。

**目标：**将已确认的黑粉双主题、居中人物入口、滚动叙事、环形项目画廊和个人内容，落地为可访问、可维护、对求职有帮助的个人网站。

**架构：**正文与详情页使用普通网页结构，项目、照片和文章由结构化内容驱动。3D 人物作为独立场景加载；滚动动画、鼠标响应和主题共享明确状态。项目画廊沿用已经认可的 CSS 3D 方案，完整站点再组件化和优化。

**拟用技术：**Next.js、TypeScript、React、Three.js / React Three Fiber、GSAP ScrollTrigger、CSS 主题变量、结构化数据与 Markdown 内容。具体稳定版本及兼容性在工程阶段核验后锁定。

04 · 阶段 2：正式工程与双主题

建议在当前目录的 site/ 中建设正式工程，根目录继续保存设计、报告与原型。工作过程中根据实际文件组织调整工程内部位置，不覆盖现有设计文件。

  • 初始化正式工程、版本控制与依赖锁文件，确定运行、检查、构建命令。
  • 建立 site/app/layout.tsx 与 site/styles/tokens.css，统一字体、颜色、间距、圆角和主题。
  • 建立 site/components/theme/ThemeController.tsx，同步背景、文字与后续场景灯光。
  • 建立 site/data/profile.ts 和项目、照片、旅行、故事内容类型。
  • 创建总览及详情页路由；普通内容能够直接访问、刷新和分享。
  • 主题选择可保留用户偏好，刷新时避免明显闪色；未选择时先采用 Light，与目前主视觉一致。

**验收：**正式网页可在本地运行并构建；主题切换不重置页面位置；联系方式不依赖图形场景加载。

06 · 阶段 4：保留并正式化画廊

  • 将当前原型拆为 site/components/projects/ProjectGallery.tsx、ProjectCover.tsx、ProjectPanel.tsx 和 ProjectDirectory.tsx。
  • 项目数据统一来自内容索引；循环位置、封面、目录和介绍引用同一项目 ID。
  • 保留最新标题、卡片尺寸和弧形；截图对照检查桌面主要呈现 4–5 张封面。
  • 入场从上方展开；鼠标方向按移动增量判定，停止移动后恢复默认向左循环。
  • 拖动、点击、键盘与触屏分清；拖动越过点击阈值后不能误开介绍。
  • 打开介绍暂停、关闭恢复；主题切换不重置顺序或当前参观位置。
  • 运行时仅更新必要位置；离开可视区域或切至后台时暂停更新，页面卸载时清理动画和事件。
  • 检查至少两轮完整首尾循环、持续操作、窗口调整和重新进入画廊。

**验收：**保留你已认可的外观；无首尾跳变、误点击、滚动卡住或主题重置。手机使用一件主体与两侧邻作，不强行塞入五张小图。

07 · 阶段 5：真实封面与完整项目案例

  • 根据公开仓库和你提供的运行条件，逐项记录现状、启动方式、访问入口与是否已运行验证。
  • 能实际运行的项目获取真实截图或录屏；运行条件不齐的项目采用明确标识的项目海报，不能伪装成运行界面。
  • 封面统一外框比例与裁切规则，保留各项目的辨识度；不把所有封面一律染成粉色。
  • 所有公开仓库进入目录；Fork 保留来源和学习 / 贡献说明。
  • 知野、Lumi、zxcvbn-MoonBit 首先补齐详细案例，其余项目按现有证据逐步丰富。
  • 案例记录：问题、你的全栈职责、Vibe coding 工作方式、技术选择、调试、验证、状态、限制和代码入口。
  • 公共元数据可在构建时更新；AI 辅助方式、本人贡献和精选顺序由内容文件维护，不被自动同步覆盖。

**招聘表达：**明确“全栈负责 · AI 辅助开发”。进一步展示你如何提出要求、取舍方案、整合系统、定位错误与验收结果；不把使用 AI 隐藏掉，也不把公开仓库存在本身当成能力验证。

**验收：**每件作品能打开介绍及准确 GitHub 地址；精选项目有真实材料和清楚边界；没有虚构性能、用户数或未完成能力。

08 · 阶段 6：真实个人 3D 模型

  • 以现有概念图为造型依据，明确正面及允许的侧面、上半身范围、略拽表情和两套服装颜色。
  • 先制作可在网页中加载的小样，检查本人辨识度、头发、眼镜与脸的比例；再完善模型。
  • 模型具备头颈肩胸控制、眼球视线、眨眼控制与必要表情形变。
  • 提供静息呼吸、轻微转头、眨眼动作；眼镜与头部正确绑定，镜片不遮挡视线。
  • 同一模型支持黑色 / 珍珠灰服装材质切换，不通过切换两张截图假装换装。
  • 交付可编辑源文件、网页 GLB、纹理、动作清单、命名和资源使用范围。
  • 检查网格、纹理大小、透明发丝开销和手机表现；必要时制作低负担版本。

**关键边界：**当前 PNG 不能直接提供真实骨骼、眨眼和侧面旋转。建模需要单独的模型制作过程或可操作的现有模型。AI 辅助生成网格也需清理与绑定，不能保证一次输出即可使用。

**验收：**能实际加载和控制 GLB；像本人、头顶完整、略拽表情自然；侧看不出现眼镜穿模或明显脸部变形。模型不合格时，保留静态首屏预览继续完善内容，但不将其称为最终真 3D。

09 · 阶段 7：首屏人物与互动

  • site/components/avatar/AvatarScene.tsx：模型加载、相机与灯光；AvatarRig.tsx：静息、眼球与头部动作。
  • 根据真实屏幕比例取景，确保头顶、导航与人物不相撞。
  • 鼠标移动时视线先跟随，头部平滑响应；离开时自然回正。
  • 拖动限制在已验收的侧看范围；触屏纵向滚动优先。
  • 主题切换同步服装材质、背景和轮廓光；动作和滚动位置保持连续。
  • 粉色光晕缓慢流动，避开正文；减少动态时取消持续漂移。
  • 加入模型加载中、加载失败与不支持图形场景的静态回退。

**验收：**操作的是实际模型，而不是整张背景图倾斜；没有明显动作冲突、眼睛翻转、穿模或闪色；模型失败也能进入正文与项目。

10 · 阶段 8：视差滚动和进入个人世界

  • 用 site/components/intro/IntroExperience.tsx 管理序幕、欢迎页与内容的连续状态。
  • 先显示居中人物；滚动后人物缓慢后移，为标题让出空间。
  • A WORLD / OF / MY OWN 全大写分组出现，中央 EXPLORE 随后出现。
  • 点击 EXPLORE：按钮回应、文字淡出、柔粉扩散、镜头轻推、个人世界进入。
  • 正常继续滚动也能进入正文；不把访客锁在入口或强制点击动画。
  • 章节之间采用低幅度视差和进场；正文阅读时保持稳定。
  • 快速滚动、向上返回、窗口改变和返回详情页都恢复正确状态。
  • 减少动态路径允许直接进入内容，不播放大幅推进。

**验收：**所有动效服从用户操作；没有滚动劫持、反复播放排队、页面突然跳位或多个滚动控制器相互冲突。

11 · 阶段 9：兴趣、生活、旅行和故事

  • 生活：建立有节奏的照片墙，支持放大、关闭、左右切换与键盘操作。
  • 旅行：上海、北京、云南各有封面和组照；云南具体地点在你给出后再细化。

  • 音乐可加入你确认的歌单或公开链接，默认不自动播放背景音。
  • 真实故事到位后再发布文章，以你的口吻整理，不预先编写人生经历。
  • 每张图片生成合适网页尺寸，记录裁切焦点、尺寸、图注和替代文本。

**验收：**照片和文字能体现你本人；手机裁切保留主体；图片加载不会造成大幅布局跳动；在素材缺失时保留设计版位供审阅，正式页面不伪造内容。

12 · 阶段 10：招聘信息和分享

  • 进入正文后，姓名、学校专业、身份与意向清楚可见。

  • GitHub 和邮箱入口稳定可用；正式简历提供后再加入查看与下载。
  • 加入页面标题、描述、分享预览图、站点图和必要的搜索信息。
  • 补充实习时间、地点偏好时同步更新个人介绍与简历。

**验收：**访客能快速找到能力证据与联系方式；直接分享项目链接能显示合理标题与图像；网站与简历口径一致。

13 · 阶段 11：整站美感和质量

  • 对照人物视觉稿和当前画廊，检查主题、字体、留白、尺寸和章节节奏。
  • 检查桌面宽屏、普通笔记本、短屏、手机竖屏与横屏，重点看不裁头、单行标题和画廊比例。
  • 在手机与桌面上检查实际加载、滚动、手势、主题和模态框，不能仅用模拟尺寸替代所有实机检查。
  • 测量初始资源、模型大小和连续动画；预算与实际测量一起记录，再决定压缩和降级。
  • 对页面不可见、离开场景、低性能设备和减少动态偏好采用合适暂停或回退。
  • 检查键盘焦点、关闭后焦点返回、文字对比度、图片替代文本与触屏手势。
  • 检查所有页面、项目目录、外链、邮件、直接刷新、返回与模型失败路径。
  • 完成正式构建和与关键行为对应的检查；小文案调整用针对性验证，不重复堆砌测试。

**验收：**不仅首页好看，内容页也统一；关键访问路径在正常和失败情况下均能完成。所有性能数值有测量依据，不能预先宣称达到。

14 · 阶段 12：发布与维护

  • 根据实际工程和目标访客测试部署环境，准备构建、静态资源与模型加载配置。

**验收：**正式地址实际可访问且核心路径复验通过；内容可以持续更新，而不是只得到一张静态截图或一次性动画演示。
