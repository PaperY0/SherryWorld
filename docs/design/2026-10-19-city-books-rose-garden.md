# WEAVER：玫瑰花园与城市手帐

## 当前背景修订

用户随后提供粉色云山、金色微光与水面倒影的参考图，并明确取消玫瑰。当前页面已使用原图 `site/public/images/life/cloud-mountains-reference.png` 作为城市书本场景、城市相册和照片放大层的背景；相册背景增加暗色遮罩。玫瑰花瓣、叶片与地面几何已删除，Three.js 画布透明，仅保留城市书本和少量金色光点。相机浏览、滚轮靠近、三类照片筛选与拍立得交互保留。下面的玫瑰描述为此前方案记录，当前不再渲染。

## 已确定的设计

按用户提供的城市顺序，广州、深圳、青岛、上海、北京各一本书。保留上一版左右开门进入 WEAVER 的形式，门后改为可交互的 Three.js 场景，不再是单张中央卡片。

暗粉色地面铺满风格化三维玫瑰。五本有厚度的手帐直立其间，分别使用玫瑰粉、鼠尾草绿、雾蓝、藕粉、暖褐布纹封面，配奶油色蝴蝶结、蕾丝边、书脊和纸页。

照片未提供，因此五城都先使用明确标注的占位内容，不虚构旅游地点、日期或人物经历。

## 参考项目中的证据

阅读对象：用户目录中的 `Meer-Mohsin-Replica/src/scenes.js`，以及抓取文件 `evidence/original.pretty.js:39144-39274`、`evidence/original.pretty.css` 的 Awards 区域。

确认：Three.js WebGLRenderer、PerspectiveCamera、GLB 地面、贴图展示平面、灯光、ACES 色调映射，GSAP/ScrollTrigger 驱动固定区域里的相机位置/转角与左右门板。抓取文件后段出现 regControls 设置，但未找到对应的完整初始化，因此不把本次鼠标拾取/缩放实现宣称为逐行复制原站控制器。

本次参考其空间展示与相机浏览方式，独立实现城市手帐、玫瑰与交互：

- 使用现有 Three.js 依赖；靠近 WEAVER 时才动态加载引擎，等待字体后绘制封面。
- 425 朵程序化玫瑰，花瓣和叶子分别用 InstancedMesh；花瓣几何与材质共享，避免每个花瓣一个绘制调用。这是风格化几何花朵，并非写实扫描模型。
- 书本由封面、封底、纸页、书脊实体组成。封面 CanvasTexture 包含中文城市名、花体英文名、布纹、花边、蝴蝶结。
- 鼠标横向移动平滑移动相机，用 Raycaster 命中实际书本；点击命中的书打开相应城市相册。顶部城市索引及底部打开按钮提供键盘和触屏替代操作。
- 完全开门期间，场景内滚轮在限定范围推动相机靠近/后退；达到范围边界后放行页面滚动。页面过渡期间不抢滚轮；触屏提供左右滑动切换与 +/− 按钮。
- 相机逐帧插值，像素比限制为 1.5，场景不在视口或页面隐藏时停止渲染；相册打开时暂停场景绘制，卸载时释放几何、纹理、材质、监听器和 renderer。
- WebGL 不可用时显示五本可点击的静态书封，仍可进入相册。

## 城市相册

每城有独立 JSON 数据源，分类为个人照 portrait、风景照 scenery、美食照 food。

复用原有弧形照片展墙的拖动、左右切换、自动播放/暂停、从上落入、点击放大和 Escape 返回。新的视觉是暖灰粉纸纹背景、奶油拍立得纸框、倾斜照片、半透明胶带、丝带与点状花边；没有沿用 Explorer 的曙光背景。

相册进出复用 `useFadingDialog`，保持透明最终帧，退出后恢复焦点及滚动位置。

## 照片放置

目录分别为 `site/public/images/life/{guangzhou,shenzhen,qingdao,shanghai,beijing}/`。

每个目录中 `photos.json` 格式如下，空数组自动使用占位图：

```json
[
  {
    "src": "/images/life/guangzhou/portrait-01.jpg",
    "alt": "照片内容的真实描述",
    "caption": "照片标题",
    "category": "portrait"
  }
]
```

实际图片放在对应目录即可。没有照片的分类显示空页说明，不伪造素材。
